# Standin 랜딩페이지 구성 명세

## 1. 페이지 목표

### Primary Goal

웹툰 작가 또는 관련 종사자가 Standin의 베타 대기 등록을 완료하도록 유도한다.

### Secondary Goal

방문자가 Standin의 제품 흐름과 현재 범위를 오해 없이 이해하도록 한다.

### 핵심 성공 조건

- Hero만 읽어도 서비스 대상과 가치가 이해된다.
- 제품 데모를 보면 “후보 제안 → 작가 선택” 구조가 이해된다.
- 페이지를 내려가며 기존 작업 대비 차이가 구체화된다.
- 현재 단계와 범위가 정직하게 드러난다.
- 마지막 CTA까지 메시지가 반복이 아니라 누적된다.

## 2. 정보 구조

### 2.1 Header

구성:
- 좌측: Standin 워드마크
- 중앙 또는 우측: `작동 방식`, `왜 Standin인가`, `FAQ`
- 우측 CTA: `베타 대기 등록`

동작:
- 섹션 앵커 이동
- 스크롤 시 반투명 배경과 얇은 하단선 적용
- 모바일에서는 메뉴 버튼 또는 핵심 CTA만 표시

---

### 2.2 Hero

목표:
- 대상, 문제, 해결 방식, CTA를 첫 화면에서 전달
- 제품의 핵심 데모를 동시에 보여줌

왼쪽 카피:
- Eyebrow: `WEBTOON 3D POSE ASSISTANT`
- H1: `콘티 속 포즈를, 그릴 수 있는 3D 시작점으로`
- 설명: 러프 콘티를 분석해 가까운 3D 포즈 후보를 제안하고, 작가가 선택·조정해 클립스튜디오 작업으로 이어간다는 내용
- Primary CTA: `베타 대기 등록`
- Secondary CTA: `작동 방식 보기`
- 보조 문구: `완전 자동이 아닌, 작가 선택 중심의 어시스트 도구`

오른쪽 비주얼:
- 콘티 카드
- 분석 가이드선
- 3D 마네킹 프리뷰
- 후보 포즈 카드 5개 중 하나가 선택된 상태
- `콘티`, `후보 검색`, `작가 선택` 단계 라벨

주의:
- 실제 제품 스크린샷이 없다면 “제품 흐름 예시”로 표기
- 너무 많은 정보나 작은 글자를 넣지 않는다.

---

### 2.3 Product Demo

ID: `demo`

목표:
- Standin의 핵심 작동 방식을 한 번의 상호작용으로 이해시킨다.

권장 형태:
- 좌측: 러프 콘티 미리보기
- 중앙: 분석 상태와 관절 오버레이
- 우측: 3D 포즈 후보 목록 및 선택된 결과
- 하단: `선택한 포즈로 시작하기` 비활성 또는 예시 버튼

인터랙션:
- 후보 카드를 누르면 오른쪽 3D 프리뷰 포즈가 바뀌는 것처럼 표현
- 실제 3D 모델이 없다면 SVG/PNG 프레임 교체로 구현
- 단계 탭: `1. 콘티`, `2. 분석`, `3. 후보`, `4. 조정`
- 자동 재생은 선택 사항이며, 사용자가 수동으로 제어할 수 있어야 함

표시 문구:
- `제품 흐름 예시`
- `Standin이 포즈를 확정하지 않습니다. 가장 가까운 후보를 비교해 직접 선택하세요.`

---

### 2.4 Problem

ID: `problem`

제목:
`포즈를 그리기 전에, 포즈를 만드는 시간이 너무 길었습니다.`

내용:
3개의 문제 카드로 구성한다.

1. `빈 인형에서 시작`
   - 컷마다 관절을 처음부터 조정해야 함
2. `맞는 소재를 직접 탐색`
   - 수많은 포즈 중 콘티와 가까운 것을 찾아야 함
3. `작화 전 반복 배치`
   - 위치와 방향을 맞춘 뒤에야 실제 밑그림을 시작할 수 있음

시각:
- 얇은 웹툰 패널 프레임
- 반복 작업을 나타내는 미니 타임라인
- 불필요하게 부정적인 감정을 과장하지 않는다.

---

### 2.5 Workflow

ID: `workflow`

제목:
`콘티에서 클립스튜디오까지, 네 단계로`

4단계:

1. `콘티 업로드`
   - 러프한 선과 인물 위치를 입력
2. `컷과 포즈 분석`
   - 인물 수, 위치, 몸의 방향과 포즈 단서를 파악
3. `가까운 후보 선택`
   - 포즈 라이브러리에서 검색된 후보를 비교
4. `조정하고 이어 그리기`
   - 필요한 부분만 수정한 뒤 기존 작화 환경으로 이동

표현 방식:
- Desktop: 수평 스텝
- Mobile: 수직 타임라인
- 각 단계에 작은 예시 이미지 또는 아이콘

---

### 2.6 Core Benefits

ID: `benefits`

제목:
`작가의 판단은 남기고, 반복 작업만 줄입니다.`

핵심 카드:

#### 후보에서 시작

정답 하나를 강요하지 않고, 고쳐 쓸 수 있는 포즈 후보를 제시한다.

#### 필요한 컷에 집중

전신·반신처럼 3D 인체가 도움이 되는 컷을 우선 처리한다.

#### 기존 도구와 연결

Standin이 작화 앱을 대체하지 않는다. 준비된 3D를 클립스튜디오 흐름에 연결한다.

#### 실패해도 되돌아갈 수 있게

맞는 후보가 없거나 인식이 어려우면 억지 결과를 만들지 않고 수동 조정으로 전환한다.

---

### 2.7 Product Principles / Scope

ID: `principles`

이 섹션은 제품의 신뢰를 만든다.

제목:
`자동화보다 중요한 것은, 작가가 계속 통제할 수 있는가입니다.`

좌측 또는 상단:
- `AI가 잘하는 일`
  - 인물 수와 대략적 위치 파악
  - 포즈와 장면 의미의 단서 분석
  - 포즈 라이브러리 검색과 후보 정리

우측 또는 하단:
- `작가가 결정하는 일`
  - 최종 포즈 선택
  - 연출에 맞는 앞뒤와 거리
  - 관절·카메라의 미세 조정
  - 최종 작화

범위 안내 배지:
- `전신·반신 우선`
- `1~2인 컷 우선`
- `클로즈업은 필요 시 스킵`
- `복잡한 가림은 수동 보정`

---

### 2.8 Clip Studio Workflow

ID: `clip-studio`

제목:
`익숙한 작업 환경을 바꾸지 마세요.`

내용:
- Standin은 독립적인 보조 도구
- 콘티 분석과 3D 후보 선택을 Standin에서 수행
- 결과를 내보내 기존 클립스튜디오 작업으로 연결
- 클립스튜디오 안에서 선화와 최종 작화를 계속 진행

시각:
`Standin 작업 캔버스 → Export → Clip Studio 작업 화면`

주의:
- 공식 제휴 또는 공식 플러그인처럼 표현하지 않는다.
- 특정 포맷 지원이 검증되지 않았다면 일반적인 `3D 결과 내보내기`로 표현한다.

### 2.9 Beta CTA

ID: `beta`

배경:
- 잉크 네이비의 강한 대비 섹션
- 코랄 포인트 사용

제목:
`다음 컷은, 빈 인형이 아니라 가까운 포즈에서 시작하세요.`

설명:
`Standin의 초기 테스트에 참여하고, 실제 웹툰 작업에 필요한 포즈와 흐름을 함께 만들어 주세요.`

폼:
- 이메일
- 선택: 작업 형태 (`개인 작가`, `스튜디오`, `어시스턴트`, `기타`)
- 선택 동의 체크박스
- 제출 버튼: `베타 대기 등록`

폼 백엔드가 없을 때:
- 입력 검증까지만 구현
- 실제 수집이 되지 않는다면 `데모 폼`임을 명시
- 존재하지 않는 등록 성공을 보여주지 않는다.

답변 원칙:
- 간결하고 정직하게
- 현재와 향후 계획을 구분
- 기술 세부사항보다 작업 흐름 중심

## 3. 페이지별 콘텐츠 밀도

- 한 섹션의 본문은 2~4문장 이내
- 카드 설명은 60자 안팎을 우선
- 긴 기술 설명은 FAQ 또는 별도 문서로 이동
- 같은 문구를 여러 섹션에서 그대로 반복하지 않는다.
- “AI”보다 “포즈 후보”, “작가 선택”, “작업 흐름”을 더 자주 사용한다.
