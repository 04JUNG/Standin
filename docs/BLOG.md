# Standin 블로그 운영

2026-11-09: 소개, 클립스튜디오 사용법, BVH·FBX 비교 3편 공개.

- 목록: `/blog/`
- 원고: `src/data/blog.ts`
- 화면: `src/pages/BlogPage.tsx`, `src/styles/blog.css`
- 설명 이미지·캡션: `src/data/blogVisuals.ts`, `public/assets/blog/`. 시연 화면의 준비된 후보 조건은 캡션에 남긴다. 이미지 크기·대체 텍스트를 지정하고 원본 확대 링크를 제공한다.
- 사용법 글은 본문 8개 소제목마다 실제 아이콘 또는 해당 단계의 화면을 제목 바로 아래에 둔다. 새 녹화·라이브 캡처의 출처와 크롭 좌표는 이미지 폴더 README에 기록한다. BVH 적용 결과 캡처와 드래그 검증 기록은 구분한다.
- 소개는 문장 검색 GIF, 사용법은 앱→클튜 직접 드래그 GIF와 파일 행 스크린샷, 형식 비교는 구조 도해 하나를 사용한다. GIF는 자동 재생하며 이미지 자체를 클릭하거나 포커스 후 Enter·Space를 누르면 정지·재생이 전환된다. 정지 시 미리보기로 돌아가고 다시 재생하면 처음부터 반복한다. 원본 확대 링크는 이미지 밖에 따로 둔다. 같은 본문 이미지를 여러 글에 반복하지 않는다.
- BVH 직접 드롭과 기존 인형에 적용하는 메뉴 경로를 구분한다. Standin-client ADR-009의 검증 기록과 현재 네이티브 파일 드래그 구현을 근거로 하며, 메뉴 경로는 공식 매뉴얼을 참조한다.
- 빌드: Vite 다중 HTML 진입점 → 서버 렌더 → 본문·메타·구조화 데이터 주입. 공개 사이트맵에도 포함한다.
- 각 글에 공식 문서 링크, 작성자·게시일, 목차, 관련 글과 다운로드 안내를 제공한다.
- 글 하단에는 ‘모든 글 보기’와 이전·다음 글 카드를 제공한다. 순서는 `blogPosts`의 편집 순서(현재 소개 → 사용법 → 형식 비교)이며 첫·마지막 글은 존재하는 방향만 표시하고 순환하지 않는다. 글 상세의 상단 메뉴는 스크롤 중에도 ‘모든 글’을 제공한다. 기존 `article-related` 구간 ID를 유지한다.
- 입력/출력 실험 결과나 속도 수치를 창작하지 않는다. 파일 형식의 일반적 능력과 Standin의 실제 결과를 구분한다.

## 측정

기존 `standin.measurement.v3` 분석 선택 동의와 first-party journey 수집을 사용한다. Google/Meta에는 기존 페이지 조회만, 상세 구간은 Standin API로만 보낸다. 동의 전 수집하지 않으며 기존 철회·만료·90일 보관을 유지한다.

`src/lib/journey.ts`의 글 경로·구간 목록과 BFF `src/journey/blogCatalog.ts`를 함께 갱신한다. 미등록값은 서버가 거절한다.

Standin-app-server #172 운영 배포와 함께 `BLOG_ANALYTICS_ENABLED = true`로 활성화한다. 분석에 동의한 새 방문부터 블로그 상세 지표가 쌓이며 이전 방문은 소급 수집하지 않는다. 동의 전 수집하지 않고 철회·삭제 처리를 유지한다. 기존 Google/Meta 페이지 조회는 각 동의 설정에 따른다. 서버가 이전 버전으로 돌아갈 때는 이 플래그를 false로 되돌리는 호환 경로가 있다.

- 조회: 기간 내 page_view가 있는 글 문서 인스턴스. 새로고침은 새 조회, 네트워크 재전송은 중복 제거.
- 방문자: 동의한 브라우저 식별자. 사람 수나 세션 수가 아니다.
- 유입: 해당 글의 utm_source 우선, 없으면 document.referrer 도메인을 고정 범주로 분류. 원문·검색어는 저장하지 않는다. internal은 직전 사이트 내부 이동이며 최초 유입으로 소급하지 않는다.
- 구간 노출: 초점이 있는 보이는 탭에서 화면에 가장 넓게 표시된 구간. 구간별 5초 이상 활성 체류도 별도 집계한다. 읽기·이해 여부를 증명하지 않는다.
- 스크롤: 본문 문서의 75%까지 뷰포트가 도달한 조회. 관련 글 영역 노출과 구분한다. 목차 점프도 포함된다.
- 활성 체류: 초점·가시 상태와 60초 활동 한계. 사이트 하단 시간은 글 평균에서 제외.
- 다운로드 안내 클릭: 글에서 홈 #beta로 이동한 조회. 파일 다운로드나 설치 완료가 아니다.

운영 대시보드의 마케팅 탭 → 블로그 유입·읽기. API `/v1/admin/marketing?days=7`의 `blog` 객체(관리자 인증 필요)로 집계를 추출한다. UI와 API 모두 같은 기간을 사용하며 일별 표는 KST이다. 조회 실패는 null/실패 안내, 수집 0건은 정상 빈 결과로 구분한다.

검증: `npm run build`, `npm run lint`. 블로그 공개 경로·구조화 데이터·앵커·동의와 전송은 빌드 검사/측정 테스트에서 검증한다. 라이브 운영 DB에는 합성 테스트 방문을 넣지 않는다.
