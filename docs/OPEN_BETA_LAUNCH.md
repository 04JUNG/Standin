## 다운로드

- 홈페이지 `#beta`에서 운영체제별 다운로드와 `/feedback/`를 제공한다. Hero·메뉴·가이드 CTA도 다운로드로 바뀐다.
- GitHub `04JUNG/Standin-client/releases/latest` API에서 자산을 읽는다. 사용자가 말한 “latest”는 별도의 고정 태그가 아니라 GitHub의 최신 공개 릴리스 지정이다.
- `Standin_*_x64-setup.exe`, `_universal.dmg`, `_aarch64.dmg`, `_x64.dmg`만 연결한다. staging, draft, prerelease, QA 설치 파일·서명·업데이터 압축 파일은 제외한다.
- API 조회가 실패하면 GitHub 최신 릴리스 페이지로 이동할 수 있다. 클로즈베타 설치 파일을 코드에 고정해 대체하지 않는다.
- **2026-10-20 확인 시 latest는 아직 `v0.1.1-beta.8`(2026-09-08)이다. 공개 전에 오픈베타 릴리스를 Latest로 지정해야 한다.** 이 PR은 클라이언트 릴리스를 게시하거나 변경하지 않는다.
- `/closed-beta/`는 기존처럼 `/#beta`로 이동한다. `/feedback/`는 다시 실제 설문 문서이며 noindex를 유지한다. `/feedback`도 정상화한다.

## 공개 순서

1. [새 시트 전용 수신기 설정](../server/open-beta-feedback/README.md)을 완료하고 새 `/exec` 주소를 발급한다.
2. 랜딩 호스트의 `VITE_FEEDBACK_ENDPOINT`를 설정한다. 공개 빌드에 반영해야 한다.
3. 실제 Google 시트에 완료·중단 응답과 이미지 저장을 점검한다. 샘플은 테스트 표시 후 정리한다.
4. 새 클라이언트 공개 릴리스에 Windows 및 지원하는 Mac 설치 파일을 올리고 Latest로 지정한다.
5. 다운로드 파일을 실제로 받아 버전·실행을 확인한 뒤 이 PR을 병합·배포한다.
6. 이벤트 선정·발표 일정을 확정하면 안내 문구를 갱신한다.

날짜만으로 자동 공개되지 않는다. 이 PR 배포 시 사전등록·카운트다운이 다운로드와 설문으로 교체된다. Apps Script 배포, 환경변수 연결 및 실제 Google 제출은 아직 완료하지 않았으므로 초안 PR로 올린다.

## 검증 기록

- `npm run lint`, `npm run build` 통과. 빌드에서 설문 관련 10개 테스트, 타입 검사, 공개 페이지 사전 렌더링·SEO·약관 검사를 수행했다.
- 360px 모바일에서 완료·중단 양쪽 경로, 필수 응답 안내, 새로고침 시 초안 복원, 수신 주소 미설정 시 제출 차단을 확인했다.
- 1280px 데스크톱에서 실제 GitHub Latest 조회로 Windows·universal Mac 설치 파일 링크를 확인했다. 양쪽 너비에서 가로 넘침과 콘솔 오류가 없었다.
- 768px 태블릿에서도 다운로드 안내와 설문 진입 및 가로 넘침이 없는 레이아웃을 확인했다.
- 새 Google 시트의 헤더 25개가 서버 스키마와 일치함을 내보낸 파일로 확인했다. 실제 Google 제출·권한·첨부 저장 검증은 수신기 배포 후 진행한다.
