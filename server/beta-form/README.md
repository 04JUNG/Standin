# 사전등록 폼 수신기 (Google Apps Script)

Formspree를 대체하는 자체 수신 엔드포인트다. 랜딩의 클로즈베타 사전등록 폼이
이 웹앱으로 POST하면 **구글 시트 기록 → 디스코드 알림 → Gmail 알림** 순으로
처리한다.

서버 비용도, 서비스 계정 키도 없다. 스크립트가 시트의 소유자 권한으로 돌기
때문에 Google Sheets API 요금이나 OAuth 키 관리가 필요 없다.

| 파일 | 역할 |
| --- | --- |
| `Code.gs` | 웹앱 본체(`doPost`) + 수동 실행 도구 |
| `appsscript.json` | 매니페스트(시간대 `Asia/Seoul`, 익명 접근 웹앱) |

## 1. 시트와 스크립트 만들기

1. 새 구글 시트를 만든다. 이름 예: `Standin 클로즈베타 사전등록`.
2. 시트에서 **확장 프로그램 → Apps Script**를 연다(시트에 바인딩된
   스크립트라 `SHEET_ID` 없이도 동작한다).
3. 기본 `Code.gs` 내용을 이 폴더의 `Code.gs`로 통째로 바꾼다.
4. 왼쪽 **프로젝트 설정 → "appsscript.json" 매니페스트 파일 표시**를 켜고,
   내용을 이 폴더의 `appsscript.json`으로 바꾼다.

## 2. 스크립트 속성 설정

**프로젝트 설정 → 스크립트 속성**에 넣는다. 저장소에는 넣지 않는다.

| 키 | 필수 | 값 |
| --- | --- | --- |
| `DISCORD_WEBHOOK_URL` | ✅ | 디스코드 채널 → 편집 → 연동 → 웹후크에서 발급한 URL |
| `NOTIFY_EMAIL` | ✅ | 알림 받을 주소. 쉼표로 여러 개 가능 |
| `SHEET_NAME` |  | 기록할 탭 이름. 기본값 `클로즈베타 사전등록` |
| `SHEET_ID` |  | 시트에 바인딩하지 않은 독립 스크립트일 때만 필요 |

## 3. 준비 실행

배포하기 전에 시트와 알림이 실제로 동작하는지 에디터에서 함수를 직접 돌려
확인한다. 웹앱을 거치지 않고 함수 하나만 실행해 보는 것이다.

Apps Script 에디터 상단 툴바가 이렇게 생겼다.

```text
💾 저장   ▷ 실행   🐞 디버그   [ 실행할 함수 ▾ ]   실행 로그
```

1. 먼저 **💾 저장**(Ctrl+S). 저장해야 드롭다운에 함수 목록이 채워진다.
2. **[ 실행할 함수 ▾ ]** 드롭다운에서 `setupSheet`를 고른다.
   (목록에 `doPost`, `getSheet_` 같은 이름도 같이 보이는데 무시한다.)
3. **▷ 실행**을 누른다.
4. 아래 **실행 로그**에 `시트 준비 완료: 클로즈베타 사전등록 (1행)`이 뜨고,
   시트 탭에 헤더 한 줄이 생겼으면 성공이다.
5. 같은 드롭다운에서 `sendTestNotification`을 고르고 다시 **▷ 실행**.
   디스코드 채널에 "연결 테스트" 임베드가, 메일함에 알림 메일이 오면 된다.
   (이 함수는 시트에 기록하지 않는다.)

### 첫 실행 때 뜨는 권한 승인

`setupSheet`를 처음 실행하면 실행되지 않고 승인 창이 먼저 뜬다. 스크립트가
시트를 고치고, 외부(디스코드)로 요청을 보내고, 메일을 보내기 때문이다.

1. **승인 필요** → `권한 검토`
2. 구글 계정 선택
3. **"Google에서 확인하지 않은 앱입니다"** → 왼쪽 아래 `고급` →
   `(안전하지 않음)으로 이동`
4. 권한 목록 확인 → `허용`

3번 경고는 정상이다. 심사를 받지 않은 개인 스크립트에는 항상 나오며, 여기서
"확인되지 않은 앱"은 본인이 방금 붙여 넣은 이 코드를 말한다.

승인이 끝나면 함수가 이어서 실행된다. 이후 실행에는 다시 묻지 않는다.

## 4. 웹앱 배포

**배포 → 새 배포 → 유형: 웹 앱**

- 실행 계정: **나**
- 액세스 권한: **모든 사용자**

두 값이 이대로여야 한다. "모든 사용자"가 아니면 방문자의 브라우저 요청이
구글 로그인 화면으로 리다이렉트되어 폼이 실패한다.

발급된 URL(`https://script.google.com/macros/s/AKfy.../exec`)을 랜딩의
환경변수 `VITE_BETA_ENDPOINT`에 넣는다.

> 코드를 고친 뒤에는 **배포 → 배포 관리 → 버전: 새 버전**으로 다시 배포해야
> 반영된다. 저장만으로는 기존 URL 동작이 바뀌지 않는다.

## 5. 요청·응답 형식

폼은 `Content-Type: text/plain`으로 JSON 문자열을 보낸다. 브라우저가
preflight(OPTIONS)를 띄우지 않는 "단순 요청"으로 만들기 위해서다 — Apps
Script 웹앱은 OPTIONS를 처리하지 못한다.

```json
{
  "email": "artist@example.com",
  "role": "artist",
  "workStatus": "active",
  "clipStudioEdition": "ex",
  "clipStudioVersion": "3",
  "mannequinExperience": "sometimes",
  "source": "discord",
  "consent": true,
  "utm_source": "", "utm_medium": "", "utm_campaign": "", "utm_content": "",
  "pageUrl": "https://…/#beta",
  "userAgent": "…",
  "website": ""
}
```

- `source`는 **알게 된 경로**(폼 항목)다. 방문 주소는 이름이 겹치지 않도록
  `pageUrl`로 보낸다.
- `website`는 허니팟이다. 사람에게 보이지 않는 필드라 값이 차 있으면 봇으로
  보고 기록하지 않는다(응답은 성공으로 준다 — 실패를 알려주면 우회한다).

이메일과 여섯 개 선택 항목, 동의는 모두 필수다. 선택 항목 값은 `FIELDS`에
정의된 코드여야 하며, 이는 랜딩의 `src/data/content.ts`의 `beta` 옵션과 같아야
한다. **폼 항목을 고치면 `Code.gs`의 `FIELDS`와
`scripts/formspree-to-csv.mjs`도 함께 고쳐라** — 시트 열이 어긋난다.

응답:

| 본문 | 뜻 |
| --- | --- |
| `{"ok":true}` | 시트 기록 완료 |
| `{"ok":true,"duplicate":true}` | 기록했고, 같은 이메일이 이미 있었다 |
| `{"ok":false,"error":"INVALID_INPUT","fields":["role"]}` | 검증 실패 |
| `{"ok":false,"error":"SERVER_ERROR"}` | 시트 기록 실패 |

Apps Script는 오류 상황에서도 HTTP 200을 주므로, 랜딩 폼은 상태 코드가 아니라
`ok` 값을 보고 성공·실패를 가른다.

디스코드·메일 발송 실패는 응답을 바꾸지 않는다. 이미 저장된 등록을 실패로
돌려보내면 사용자가 중복 제출하기 때문이다. 실패는 Apps Script **실행 기록**에
남는다.

## 6. 시트 열

`접수시각(KST)`, `이메일`, 선택 항목 6개(라벨로 기록), `수신동의`,
`utm_source`·`utm_medium`·`utm_campaign`·`utm_content`, `유입 페이지`,
`브라우저`, `비고` 순이다.

코드가 아니라 한글 라벨을 적는다 — 사람이 읽는 표이기 때문이다. 정의에 없는
값이 들어오면 값을 잃지 않도록 원문을 그대로 적는다.

## 7. 한도

| 항목 | 무료 한도 |
| --- | --- |
| `MailApp` 메일 발송 | 하루 100통 |
| `UrlFetchApp` 외부 요청 | 하루 20,000회 |
| 스크립트 실행 시간 | 요청당 6분 |

Formspree 무료 플랜의 월 50건과 달리 **제출 건수 자체에는 한도가 없다.**
알림 메일만 하루 100통 제한을 받는다.

## 8. 누락 알림 보정

Formspree 월 한도로 알림이 가지 않은 등록은 시트에 옮긴 뒤
`resendMissedDiscordAlerts`로 다시 보낸다. 함수 안 `ROWS` 배열에 해당 행
번호를 넣고 실행하면 "지연 알림"으로 표시된 임베드가 디스코드에 올라간다.
